# ClipShot C1 — Rename to ClipShot + Capture Foundation

Plan date: 2026-08-21. Spec: `docs/superpowers/specs/2026-08-21-sizeup-capture-merge-design.md`
(approved 2026-08-21). Branch: `c1-capture-foundation`, off `main`.
Prerequisite: M5 merged, `swift test` green — 240 tests passing (verified 2026-08-21;
probe 15).

## Why this milestone exists

C1 is the merge's foundation, and it does two things at once because they touch the same
files: the app is **renamed ClipShot** (decision 1), and the **capture pipeline's first
working form** lands — screenshot region select → clipboard/file — behind a redesigned
menu and settings shell (decisions 2, 3, 6). After C1, the merged app is a daily driver
for both jobs, minus annotation (C2), recording (C3), the editor (C4), and scroll capture
(C5).

## What was measured before planning

Thirteen throwaway probes plus three baseline checks (not committed) established the API
shapes this plan asserts. They exist because four of them would have been wrong if
guessed (1, 2, 3, 14):

1. **`SCScreenshotManager` has no instance.** The one-shot capture is the class method
   `SCScreenshotManager.captureImage(contentFilter:configuration:completionHandler:)`
   (available macOS 14.0+; the newer `captureScreenshot…`/`SCScreenshotConfiguration`
   pair is 26.0-only and not usable on the 14.0 floor). `SCStreamConfiguration`'s
   `width`/`height`/`showsCursor` are `Int`/`Bool`, not the C int sizes.
2. **`NSWindow.windowNumber` == `SCWindow.windowID`**, verified live: a probe window's
   AppKit ID matched the `SCWindow` returned by `SCShareableContent` for the same window.
   This is C3's exclusion mechanism (`SCContentFilter(display:excludingWindows:)`) and it
   is the same identity `WindowKit`'s private `_AXUIElementGetWindow` bridge produces —
   one ID space, no translation. (Also: a window off-screen is absent from
   `onScreenWindowsOnly: true` results; exclusion must tolerate a border window that is
   not yet in the inventory.)
3. **`CGWindowLevelKey.overlayWindow` is 102 — the same level the Rust app used**
   (`kCGOverlayWindowLevel` is `#define`d to 102 in the SDK header; the Rust overlay set
   exactly this). The pitfall is the Swift case *spelling* — it is `.overlayWindow`, not
   `.overlay`/`.normal` (probes 3–4: those do not compile). 102 sits above the menu bar
   (24), status items (25), and normal windows (0); the overlay uses it.
4. **Mouse location without AppKit**: `CGEventSource(stateID:)` → `CGEvent(source:)` is
   **failable in Swift** (returns `CGEvent?`); `.location` is the Swift name for
   `CGEventGetLocation`. The capture target imports only CoreGraphics, so it uses this,
   not `NSEvent.mouseLocation`.
5. **Carbon modifier masks and vkey constants** for the three new defaults, measured:
   `NSEvent.ModifierFlags([.control, .command]).rawValue == 1_310_720` (same value as
   the existing `ctrlCmd` constant in `DefaultKeymap`); `kVK_ANSI_A == 0`,
   `kVK_ANSI_Z == 6`, `kVK_ANSI_S == 1`.
6. **Hotkey collisions**: ⌃⌘A / ⌃⌘Z / ⌃⌘S are free in `DefaultKeymap` (15 bindings:
   ⌃⌥⌘ arrows, ⌃⌥⇧ arrows, ⌃⌥⌘ M/C//, ⌃⌥ ←/→, ⌃⌘ ←/→) and against macOS 26's built-ins
   (which use ⌃⌥ + `fn`, not ⌃⌘ alone).
7. **`SCWindow` in the macOS 26 SDK exposes only `windowID`, `title`, `windowLayer`** —
   no owner-name property, so UI that names windows (none in C1) is not a concern.
8. **`CGEvent` is failable** (probe 4) — every use unwraps rather than force-unwrapping;
   a session with no event source degrades to the main display.
9. **`CGWindowLevelKey` Swift cases are spelled `…Window`** (`.overlayWindow`,
   `.screenSaverWindow`) — the un-suffixed spellings do not compile.
10. **The screen-recording permission is already granted to this bundle** on the dev
    machine (measured: `CGPreflightScreenCaptureAccess() == true` for a fresh probe)
    because ClipShot was run from the same development identity; a clean user will see
    the one-time prompt the plan specifies.
11. **The user's live settings file** at `~/Library/Application Support/Sizeup2/settings.json`
    exists with a hand-edited 2-span cycle (`1/2`, `1/3`) and empty overrides — C1's
    migration must carry exactly this forward, which is the manual check's first item.
12. **No `~/.config/clipshot/config.ini` exists** on this machine (measured), so
    `ClipShotImporter` is exercised by its tests and the disabled-menu-item path, not by
    a live import.
13. **`swift build` from a stale `.build` fails** with "missing required module
    'SwiftShims'" (module cache bound to another account's home). `rm -rf .build` first;
    a clean build of the current tree takes ~50 s and is green — the verified baseline
    every task starts from.

14. **Text renders AppKit-free.** `CTFontCreateUIFontForLanguage` + `CTLineDraw` into a
    bitmap context draws "Step 1" with system font metrics using only CoreGraphics +
    CoreText + Foundation (no `NSFont`) — this is what lets `Annotation` keep its
    AppKit-free rule while the C2 renderer draws text, despite the Rust app using
    `NSFont`.
15. **The package builds clean and current tests are the baseline** — `rm -rf .build &&
    swift build` succeeds (probe 13's fix); `swift test` is green before C1 touches
    anything, so the first C1 failure is a C1 failure, not a stale-cache artifact.
16. **`SCStreamConfiguration.showsCursor`** exists on the 14.0 floor (C3's cursor
    toggle), and `showMouseClicks` is 15.0-only — C3's ripple setting therefore drives
    our own composited ripples on 14, never the system property.
17. **`SCShareableContent.excludingDesktopWindows(false, onScreenWindowsOnly: true)`** is
    the call that returns both displays and windows in one fetch (probe 2 used it);
    `false`/`true` is deliberate — the overlay must see the desktop and the Dock, and
    C1 captures the whole display, not a window subset.

## Scope decisions

### The rename is C1's first task, not a separate milestone

The design's §Renaming table is the spec: display name, executable, `.app`, SPM package
name, settings path (+ one-time migration), save prefix, menu-bar icon, app icon all
become ClipShot; **the bundle identifier stays `com.lliu.sizeup2`** (the Accessibility
grant is bound to it) and signing is unchanged. `SizeUp` — the other product whose plist
the app imports — is never renamed. Doing the rename first means every later capture
string is written once, correctly.

### Three new targets, not one

The design's §Architecture table stands: `Capture` (ScreenCaptureKit, no AppKit),
`Annotation` (model only in C1; CoreGraphics-only like `Geometry`), `OverlayUI` (AppKit).
The `Recording`, `Stitching`, `ToolbarUI`, `EditorUI` targets arrive with C3/C5.
`lint-layering.py` gains rows for the three new targets in Task 2 — before code lands in
them — so the first review of capture code sees the layering enforced.

### The overlay is a C1 feature with a C2-shaped interface

C1's overlay does region selection and the three outcome actions (clipboard / file /
cancel). C2 adds the annotation canvas. The overlay view therefore exposes the seam C2
will implement — `attach(annotations:)`, the toolbar's anchor point, the screenshot
bitmap — now, so C2 does not restructure C1's window. C1 draws the screenshot and the
selection rectangle; C2 replaces the drawing body, not the window.

### What C1 does NOT do

- No annotation tools, toolbar, style panel (C2).
- No recording, border window, or editor (C3/C4). No scroll capture (C5).
- No `Recording`/`Stitching`/`ToolbarUI`/`EditorUI` targets.
- No changes to window-manager behaviour. The 15 window actions, routing, Spaces,
  cycling, gaps, and skip list are untouched except where the rename touches their strings.
- No StoreKit/App Store work (already out of scope in the design).

## Architecture

```
Geometry ── Config ── App
   ├─ Core ──────────┤
   ├─ WindowKit/SpaceKit/Hotkeys
   └─ Capture ── OverlayUI ── App
        └─ Annotation
```

New edges: `App` → `Capture`/`Annotation`/`OverlayUI`; `OverlayUI` → `Capture`/`Annotation`.
Nothing existing gains a dependency except `App` (which is unconstrained by the lint).

### Settings migration

`SettingsStore.defaultURL` moves to `~/Library/Application Support/ClipShot/settings.json`.
At launch, before `load()`: if the new file is absent and the old `Sizeup2/settings.json`
exists, `FileManager.moveItem` it (creating the `ClipShot/` directory). If the new file
already exists, the old one is left in place and an `NSLog` names both paths — never
overwritten, because a second copy is recoverable and a destroyed original is not. The
migration is one function in `Config` (`SettingsStore.migrateFromLegacy()`), tested with a
fake `FileManager` seam the same way the store's URL is injected.

### Hotkeys

`Action` gains three cases: `.captureScreenshot`, `.startRecording`, `.toggleScrollCapture`.
They are routing identifiers only; `cycles`/`isPlacement` both return `false` for them, so
`ActionRouter` (whose `perform` switch is exhaustive) and `FrameMath.placement` (guard-based,
so it silently rejects them — correct: a capture action is never frame math) need no logic
change. `DefaultKeymap` gains the three measured defaults; `KeymapResolver`,
`ShortcutSetting`, `ActionIdentifier`, `KeyName`, and `HotkeyManager` are unchanged
mechanically — they operate over `Action` and pick up the new cases. `AppDelegate`'s hotkey
registration loop routes capture actions to `CaptureSession` instead of `router.perform`.

### CaptureSession

A small `@MainActor` state machine in `App` (not `Core`: it drives AppKit windows).
States: `.idle`, `.capturing`, `.recording`, `.scrollCapturing`, `.editing`. C1 implements
`.idle ⇄ .capturing`; the other states exist as cases with no events reaching them until
C3–C5. One `transition(_ event:)` function is the only way state changes; the menu rebuild
and status icon are *derived* from the state (this replaces ClipShot's
`enter_recording_mode`/`exit_recording_mode` mutation pair — design §Architecture).
A capture hotkey in the wrong state is ignored with an `NSLog`.

### `Capture` target surface (C1)

- `ScreenCapturePermission.hasAccess / requestAccess` — `CGPreflightScreenCaptureAccess` /
  `CGRequestScreenCaptureAccess`.
- `DisplayInventory` — async `SCShareableContent.excludingDesktopWindows(false,
  onScreenWindowsOnly: true)`; `display(matching: CGDirectDisplayID)` and
  `window(matching: CGWindowID)` via `windowID` (probe 2).
- `Display` lookup — `display(containingCursor:)` (probe 4: failable `CGEvent`) and
  `display(forAppkitFrame:)` (center-point, top-left conversion, matching the discipline
  `WindowKit` uses; negative-origin displays included in tests).
- `Screenshot.capture(display:excludingWindows:pixelSize:showsCursor:) -> CGImage?` — the
  class method, probe 1; `pixelSize` is the even-rounded selection size.
- `even(_:)` dimension helper.

### `OverlayUI` surface (C1)

- `OverlayWindow` — borderless, keyable (a `canBecomeKeyWindow`-true subclass), level
  102 (`CGWindowLevelKey.overlayWindow`, probe 3), one per target display, clear
  background, no shadow. Shows the captured screenshot as its content image.
- `OverlayView` — draws the screenshot, a dimmed veil, the selection rectangle with a 1pt
  white border, and a size label at the cursor; mouse-drag selects; Esc cancels; Enter
  confirms; **`confirm` fires a callback with the normalized selection in display
  top-left points** — `App` converts to pixels with the display's backing scale.
- `Annotation`-aware seam (unused until C2): `attach(annotations: [])`.

### Menu (decision 2)

```
[permission/hotkey banners, when applicable — existing behaviour]
─────────────
Screenshot                          ⌃⌘A
Record Screen                       ⌃⌘Z   (no-op + alert until C3)
Scroll Capture                      ⌃⌘S   (no-op + alert until C5)
─────────────
Window ▸   (halves | quarters | full screen/center/snap back)
Display ▸  (next/previous)
Spaces ▸   (next/previous)
─────────────
Settings…                           ⌘,
Help                                (docs site)
─────────────
Quit ClipShot                       ⌘Q
```

During `.capturing` the menu collapses to: `Stop…` (re-enters confirm, ⌘-less), separator,
Settings…, Quit. `Record Screen`/`Scroll Capture` are listed with their shortcuts but
perform a one-time "coming in a later build" alert until C3/C5 — honest about absence, and
they must **not** be hidden (a hidden binding with a dead key is the failure mode M1
fought). All of today's per-item annotations (no-shortcut, claimed-by, unavailable) move
into the submenus unchanged. The status icon becomes ClipShot's template asset
(`Resources/statusbar_icon.png`, decoded + `isTemplate = true`, SF Symbol
`rectangle.split.2x1` fallback on decode failure); problem state keeps the warning triangle.

### Settings (decision 3)

Same shell (`PreferencesWindow`: reused window, reload-on-show, activate-first). Three tabs:

1. **General** — Launch at login (moved here from the menu; same `SMAppService`
   degradation); Permissions section: live rows for Accessibility and Screen Recording
   (granted / not-granted + "Open System Settings" deep links); Capture section: the two
   toggles from decision 5 (`showCursorInRecordings`, `showClickRipples`, both default on,
   wired to `Settings.capture` — persisted now, consumed by C3).
2. **Window** — today's General tab content, renamed.
3. **Shortcuts** — existing recorder, 18 rows in two sections (Capture: 3; Window: 15),
   `Restore Defaults`, and **two** import buttons: `Import Shortcuts from SizeUp…` and the
   new `Import Shortcuts from ClipShot…`, each disabled + tooltip when its source file is
   absent, both with the existing confirm-then-report flow (they replace **all**
   overrides). The import menu items leave the status menu.

## Task 3 — `Capture` target

  `Sources/Capture/{Permission.swift,Display.swift,Inventory.swift,Screenshot.swift}`,
`Tests/CaptureTests/*.swift`. No AppKit (lint row, Task 2).

**Interfaces:**
- `ScreenCapturePermission` (probe 10): `static var hasAccess: Bool`,
  `@discardableResult static func requestAccess() -> Bool`.
- `DisplayLocation`: `display(containingCursor:) -> (id: CGDirectDisplayID, bounds: CGRect)?`
  (probe 4: failable `CGEvent`; `CGGetDisplaysWithPoint`; main-display fallback),
  `display(forAppkitFrame:) -> (id, bounds)?` (center-point top-left conversion; the
  AppKit frame comes in bottom-left — the same conversion `WindowKit.Coordinates` performs,
  duplicated here deliberately because `Capture` may not import `WindowKit`; both are
  tested against the same fixture).
- `DisplayInventory` (probe 2): `static func current() async throws -> DisplayInventory`;
  `func display(matching:) -> SCDisplay?`, `func window(matching:) -> SCWindow?`.
- `Screenshot.capture(_:excludingWindows:pixelSize:showsCursor:) async -> CGImage?`;
  `Screenshot.even(_:) -> Int`.

- [ ] **Step 1: `Permission`** — two functions, one file. (No test beyond compile: the
  preflight is a TCC syscall; manual checklist covers it.)
- [ ] **Step 2: `Display`** — both lookups. The cursor lookup must degrade to
  `CGMainDisplayID()` when the event source is nil (probe 8) rather than trap.
- [ ] **Step 3: `Inventory` + `Screenshot`** — the one-shot call with `width`/`height`
  (`Int`, probe 1) and `showsCursor`; `excludingWindows` from an `SCWindow` match;
  an unmatched exclusion is captured *without* it (the window may have closed — the
  Rust app's documented behavior), never a failed capture.
- [ ] **Step 4: `even`** — `x & ~1`; H.264 requires even dimensions; a 1pt selection
  rounds to 0 and the caller treats that as "too small" (that guard lives in `App`,
  matching ClipShot's 5pt minimum).

### Tests

`DisplayTests` with an injected display-table seam (a `DisplayLookup` protocol the
production code satisfies with CoreGraphics — the same injection pattern `WindowKit`
uses for screens):

1. `cursorInPrimaryDisplayResolvesToIt` / `cursorInSecondaryResolvesToIt`.
2. `negativeOriginDisplayIsFound` — a display positioned left/above the primary; the

3. `cursorOnANoDisplayFallsBackToMain` — the failable-event path.

checklist. (The class method, the failable event, and the `SCWindow` matching were all
