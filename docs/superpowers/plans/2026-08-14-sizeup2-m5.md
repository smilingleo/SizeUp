# M5 — Spaces

The last milestone. When it lands, SizeUp can be uninstalled.

## What this is for

SizeUp binds four Spaces shortcuts, all of which the author uses: `⌃⌘→` next, `⌃⌘←` previous, `⌃⌘↑`
above, `⌃⌘↓` below. Two of them cannot be reproduced, and the plan says so up front rather than
discovering it in task 4 — see "Above and below are gone" below.

## What was measured before planning

M2's deferred findings predicted that moving a window between Spaces would need a wider `WindowHandle`
exposing a title-bar point, because the known technique is to simulate a drag onto a Mission Control
thumbnail. **That prediction was wrong**, and it was checked rather than reasoned about. Throwaway probes
(kept in `.superpowers/sdd/2026-08-14-sizeup2-m4/`) established on macOS 26.5.1, SIP enabled:

- Every private SkyLight symbol needed resolves via `dlopen`/`dlsym` on
  `/System/Library/PrivateFrameworks/SkyLight.framework/SkyLight`: `SLSMainConnectionID`,
  `SLSCopyManagedDisplaySpaces`, `SLSMoveWindowsToManagedSpace`, `SLSGetActiveSpace`,
  `SLSCopySpacesForWindows`, `SLSManagedDisplaySetCurrentSpace`. The older `CGS`-prefixed aliases resolve
  too.
- `SLSMoveWindowsToManagedSpace` **actually moves a window**, verified by reading the window's space back
  with `SLSCopySpacesForWindows` before and after. No drag, no title-bar point, no screen coordinates, no
  scripting addition.
- `SLSManagedDisplaySetCurrentSpace` switches the active space and can switch back, so a moved window can
  be *followed*.
- `_AXUIElementGetWindow`, `dlsym`'d from ApplicationServices, returns a valid `CGWindowID` for an
  `AXUIElement` — the bridge from what `WindowKit` has to what SkyLight wants.
- The author's live layout: built-in display has `ManagedSpaceID`s `[1, 3]`, external has `[288]`.

So this milestone is a private-API wrapper plus routing, not a redesign.

## Above and below are gone, and that is not a bug we can fix

macOS arranged Spaces in a grid until Lion. It has been a single horizontal strip per display ever since,
and there is no API for a vertical neighbour because there is no vertical neighbour. `⌃⌘↑`/`⌃⌘↓` in the
author's SizeUp configuration have not moved a window in over a decade; they are dead keys that were
never noticed.

The decision: **do not invent behaviour for them.** Mapping above→previous and below→next would be a
guess dressed as a feature, and the failure mode is a window vanishing to a Space the user did not ask
for. Instead:

- `SpaceSequence` returns `nil` for `.above`/`.below` with the reason in a doc comment.
- The importer **skips** SizeUp's `Space Above`/`Space Below` entries and reports them as skipped, so the
  import alert names them. The user learns why from the one screen where it is relevant.
- The Shortcuts tab lists 15 actions: the existing 13 plus `Next Space` and `Previous Space`.

## Risks specific to this milestone

**This is the first milestone that uses private API.** A wrong symbol signature is a crash, not a
compile error, and `unsafeBitCast` to a `@convention(c)` function type will happily accept nonsense.
Every symbol therefore resolves optionally, and *every* entry point degrades to doing nothing if any
symbol is missing — a future macOS that drops one must leave the other twelve shortcuts working.

**A window moved to another Space while the user stays put is a window that has apparently vanished.**
Hence the follow-the-window setting, and hence it defaults to *on*: that is what SizeUp does and what
the muscle memory expects.

## Tasks

### Task 1 — `SpaceSequence`, the only part of this that is pure

New `Sources/Geometry/SpaceSequence.swift`. `DisplaySequence` is the precedent to follow.

```swift
public func neighbouringSpace(
    from current: SpaceIdentifier,
    in spaces: [SpaceIdentifier],
    direction: Direction
) -> SpaceIdentifier?
```

`SpaceIdentifier` is a `UInt64` wrapper (`Hashable`, `Sendable`) so a space ID cannot be passed where a
window ID is wanted — this milestone juggles three different opaque integer IDs and they are easy to
confuse.

Must handle, each with a test: the ordinary neighbour both ways; **wrap-around** at both ends (SizeUp
wraps, and a non-wrapping version silently does nothing at the end of the strip, which reads as broken);
`current` absent from `spaces`; a single-space display (no neighbour, so `nil`); an empty list;
`.above`/`.below` → `nil`.

`Geometry` imports CoreGraphics only. This file needs neither, and must import nothing.

### Task 2 — `SpaceKit`, the private-API wrapper, quarantined in one target

New target `SpaceKit` (`Sources/SpaceKit/`), depending on `Geometry` only. This is the *only* place in
the project allowed to touch private API, so that the blast radius of a macOS change is one directory.

- `SkyLight.swift` — one `dlopen`, every symbol resolved **optionally** and once, in a `let` on a
  `Sendable` type. Each `@convention(c)` typealias gets a comment giving the signature it is asserting
  and where that came from, because a wrong one is a crash rather than a compile error.
- `SpaceService.swift` — the useful surface:
  - `displaySpaces() -> [SpaceLayout]` where `SpaceLayout` is `{ displayIdentifier: String, spaces:
    [SpaceIdentifier], current: SpaceIdentifier }`, parsed from `SLSCopyManagedDisplaySpaces`. Parse
    defensively: it returns a plist-shaped `CFArray` of dictionaries and every level must be optional.
  - `spaces(of windowID:) -> [SpaceIdentifier]`
  - `move(windowID:to:) -> Bool`
  - `activate(_ space:, onDisplay:) -> Bool`
  - `isAvailable: Bool` — false if any needed symbol is missing.
- `WindowIdentifier.swift` — `windowID(of: AXUIElement) -> CGWindowID?` via `_AXUIElementGetWindow`.

Tests can cover the *parsing* (feed it a dictionary shaped like the real one, captured from the probe
output) and the degradation path. They cannot cover the moves; say so.

### Task 3 — the seam in `Core`, and routing

`Core` must not import Foundation, so it cannot see `SpaceKit`. Define the seam the way `ScreenProvider`
already is:

```swift
public protocol SpaceControlling: Sendable {
    var isAvailable: Bool { get }
    func layout(containing windowID: UInt32) -> (spaces: [SpaceIdentifier], current: SpaceIdentifier, display: String)?
    func move(windowID: UInt32, to space: SpaceIdentifier) -> Bool
    func activate(_ space: SpaceIdentifier, onDisplay display: String) -> Bool
}
```

`WindowHandle` gains `var windowID: UInt32? { get }`. `ActionRouter`'s `case .space` becomes: get the
window ID, get the layout, ask `neighbouringSpace`, move, and follow if configured. Every step returns
early on failure.

A space move must **not** record a placement or advance the size cycle — the window's frame does not
change. Pin that with a test: snap back after a space move must still restore the pre-*placement* frame.

Test with a fake `SpaceControlling`, as the router's other collaborators already are.

### Task 4 — settings and defaults

- `Config.Settings.followsWindowToSpace: Bool`, **default `true`** (SizeUp's behaviour).
- `DefaultKeymap` gains `.space(.next)` = `⌃⌘→` and `.space(.previous)` = `⌃⌘←`, matching the author's
  plist exactly (`ComboFlags` 1310720 → Carbon 4352). `matchesTheUsersSizeUpConfiguration` must be
  extended, and the shortcut count becomes **15**.
- `SizeUpImporter` skips `Space Above`/`Space Below`, reporting them in `skipped`.
- General tab: a toggle for following, with a sentence explaining what happens if it is off.

### Task 5 — wiring

`App` constructs `SpaceService` and injects it. `AXWindow` implements `windowID`. If `SpaceService`
is unavailable, the two Spaces shortcuts must still *register* and simply do nothing, and the status
menu must say why next to them rather than pretending they work.

### Task 6 — verification and documentation

`docs/superpowers/M5-manual-verification.md`, deferred findings, README (M5 done, SizeUp can be
uninstalled, and a plain statement that private API is used and what happens when it breaks).

## Definition of done

`swift test` passes with meaningfully more tests; zero release warnings; the author can move a window to
the next and previous Space on both displays, with and without following, and uninstall SizeUp.
